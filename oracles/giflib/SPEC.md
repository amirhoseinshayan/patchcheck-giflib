# giflib `gif2rgb` — independent reference behaviour

Status: written by the group from the GIF89a specification and the documented
behaviour of `gif2rgb`. Expected outputs are derived from this document, never
from running any version of the program. The inputs and oracle JSON files are
generated by `tools/gen_giflib_corpus.py`.

Target program: `gif2rgb` from giflib (SourceForge), the `-1` mode that writes
one interleaved RGB stream to standard output. The real defect under test is
CVE-2016-3977, a heap-buffer-overflow in `util/gif2rgb.c` (`DumpScreen2RGB`).

## Invocation

`gif2rgb -1 FILE`. The program decodes the GIF, builds the logical screen and
writes raw RGB bytes to stdout. Our tests use only the global color table and a
single, non-interlaced image.

## Rendering (valid inputs)

1. Allocate the logical screen `SWidth × SHeight` and fill every pixel with the
   file's background-color index.
2. Overlay the image at its `(Left, Top)` for `Width × Height` pixels, taking the
   pixel indices from the decoded image data.
3. Write the screen row by row, top to bottom; for each pixel emit the Red, Green
   and Blue bytes of the global color table entry at that pixel's index.

Output is therefore exactly `SWidth × SHeight × 3` bytes, stderr is empty and the
exit code is 0.

## Errors

On these conditions `gif2rgb` prints one line to stderr and exits non-zero
(value 1); stdout is empty:

| Condition | stderr |
|---|---|
| Logical screen width or height is 0 | `Image of width or height 0\n` |
| An image is not inside the logical screen (`Left+Width > SWidth` or `Top+Height > SHeight`) | `Image N is not confined to screen dimension, aborted.\n` |

(`N` is the 1-based image number.)

## Security property

No input may cause an out-of-bounds memory access. In particular, the
background-color index must be within the color table used for output. An index
`< 0` or `>= ColorCount` must be rejected, not used to read the color table:

| Condition | correct behaviour |
|---|---|
| Background-color index `>= ColorCount` of the color map | stderr `Background color out of range for colormap\n`, exit 1 |

The vulnerable version instead reads `ColorMap->Colors[index]` past the end of
the table (`DumpScreen2RGB`, the per-pixel loop), a heap-buffer-overflow READ.
